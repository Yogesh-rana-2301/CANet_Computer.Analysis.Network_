The TCP/IP model is commonly represented as 4 layers:

1. Application
2. Transport
3. Internet
4. Network Access (Link)

Some books show 5 layers by splitting physical transmission from link-layer framing, but the 4-layer view is most common in TCP/IP discussions.

## 1) Application Layer

### Responsibility

Provides network services directly to user applications.

### Common Protocols

- HTTP/HTTPS
- DNS
- SMTP, IMAP, POP3
- FTP/SFTP
- DHCP
- SSH

### Data Unit

- Message (or application data)

### Typical Devices/Systems

- clients, servers, proxies, API gateways

## 2) Transport Layer

### Responsibility

Provides process-to-process communication between endpoints.

### Core Functions

- segmentation and reassembly
- multiplexing with ports
- reliability (TCP)
- flow and congestion control (TCP)

### Protocols

- TCP
- UDP

### Data Unit

- TCP segment
- UDP datagram

## 3) Internet Layer

### Responsibility

Provides logical addressing and routing across networks.

### Core Functions

- source and destination IP addressing
- packet forwarding by routers
- path selection (with routing protocols in practice)
- control messaging and diagnostics

### Protocols

- IPv4 / IPv6
- ICMP
- ARP (IPv4 environments)

### Data Unit

- Packet

### Typical Devices

- routers, Layer 3 switches, firewalls

## 4) Network Access (Link) Layer

### Responsibility

Handles local network delivery and media access.

### Core Functions

- framing
- MAC addressing
- error detection at frame level (for example, FCS)
- media access control on shared channels

### Technologies

- Ethernet
- Wi-Fi
- PPP

### Data Unit

- Frame (then bits on the medium)

## Layer Interaction (Encapsulation)

When sending data:

1. Application creates message.
2. Transport adds TCP/UDP header.
3. Internet adds IP header.
4. Link layer adds frame header/trailer.
5. Physical medium carries bits.

When receiving data, the reverse happens layer by layer.

## Practical Example

If a laptop opens https://example.com:

1. Application layer creates DNS and HTTPS messages.
2. Transport uses UDP for DNS (usually) and TCP for HTTPS.
3. Internet layer uses IP for routing to remote server.
4. Link layer transmits frames over Wi-Fi/Ethernet at each hop.

## Mapping to Troubleshooting

- App issue: HTTP errors, DNS failure.
- Transport issue: port blocked, TCP resets, packet loss effects.
- Internet issue: wrong routing, unreachable networks.
- Link issue: cable faults, Wi-Fi interference, duplex mismatch.

## Quick Summary

The TCP/IP layers divide networking into practical responsibilities, making it easier to design, operate, secure, and troubleshoot modern networks.
